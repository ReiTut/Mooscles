What was taken
  Only the path data ("d") of the male front and back diagrams: the BODY silhouette and the
  muscle paths, with both sides already drawn (side CENTER). Not taken: the female diagrams,
  the body photographs, the region crop boxes and any code.

What changed
  1. Grouping. The muscle paths are grouped into the 17 regions of the Mooscles spec, one
     <g id="REGION"> per region in body-front.svg and body-back.svg, both sides together. Each
     path keeps its MuscleMap id in data-source (the group name where the source has no id):
       CHEST                                            -> CHEST
       SHOULDER_FRONT, SHOULDER_SIDE, SHOULDER_REAR     -> SHOULDERS
       BICEPS                                           -> BICEPS
       TRICEPS                                          -> TRICEPS
       FOREARM                                          -> FOREARMS
       CORE, OBLIQUE                                    -> ABDOMINALS
       TRAPEZIUS                                        -> TRAPS
       RHOMBOID                                         -> MIDDLE_BACK
       LATISSIMUS                                       -> LATS
       LOWER_BACK                                       -> LOWER_BACK
       GLUTEUS                                          -> GLUTES
       QUADRICEPS (and the two QUADS paths with no id)  -> QUADRICEPS
       HAMSTRINGS                                       -> HAMSTRINGS
       ADDUCTOR                                         -> ADDUCTORS
       ABDUCTOR                                         -> ABDUCTORS
       CALVES                                           -> CALVES
     The source has no neck surface: the app draws NECK with the TRAPS paths (in code; the SVGs
     have no NECK group).
  2. Rounding. None in effect. The generated Kotlin writes each number with at most one decimal,
     the source's own precision, and the generator stops if that would move any number. The path
     strings are only re-spaced (a repeated command letter is left out, "405.0" becomes "405").
     The viewBox (0 0 1024 1536) is kept, with no rescaling.
  3. Restyle. The source's colors are not used. The app fills the silhouette and the regions
     with its own neutral, primary and secondary tokens and outlines them with its hairline
     stroke (BodyMap.kt). The geometry is not changed.
